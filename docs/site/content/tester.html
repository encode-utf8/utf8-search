API Key 是什么？

  • 它是什么：本搜索服务的访问凭证，由部署者在服务端配置 UTF8SEARCH_API_KEYS=key1,key2（逗号分隔、可多个；留空 = 关闭鉴权）。 说明站本身是静态页面，不需要 Key——Key 只用于直连搜索 API。
  • 什么时候要：GET /health 返回 auth_enabled=true 时必须带 Key，否则 401； MCP 的本地 stdio 通道免 Key（本机可信），HTTP/HTTPS 通道与 REST 一样要带。
  • 去哪里拿：自己部署 → 看服务器的 .env（UTF8SEARCH_API_KEYS，或部署时你自己设的值）； 用别人的服务 → 找服务提供者申请。本站不保存、不展示任何 Key。
  • 怎么传（三选一）：Authorization: Bearer <key>（推荐，MCP/REST 通用）、 X-API-Key: <key>、请求体 {"api_key": "<key>"}（仅 REST）。MCP 只支持前两种请求头。
  • 报错怎么读：401 = Key 缺失/错误；429 = 触发限流（默认每 Key 60 次/分钟）， 看 Retry-After 等几秒再试；/health 不需要 Key，可先用它确认服务是否开了鉴权。
  • 安全：Key 等同密码，别提交进仓库或贴到公开页面；测试台的「记住」只写本标签页 sessionStorage，关掉标签页即失效。
