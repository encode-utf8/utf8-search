## 1. 先决条件

### 1.1 启动 SearXNG（搜索聚合后端，必须）

```powershell
cd C:\Users\86159\Desktop\utf8-search
docker compose up -d searxng
```

- 容器的 JSON 接口暴露在 `http://127.0.0.1:8888`。
- **首次查询需要 20–60 秒加载引擎**，期间会返回 502，属正常现象；本服务的基准脚本与客户端会自动重试一次。
- 健康检查：`curl http://127.0.0.1:8888/healthz`。

### 1.2 两种运行模式

| 模式 | 命令 | 用途 |
| --- | --- | --- |
| stdio（默认） | `utf8-search` | 本地 IDE / 桌面客户端（Claude Desktop、Codex、Cursor、Cherry Studio） |
| serve | `utf8-search serve --host 0.0.0.0 --port 8000` | 远程 / 多人共用（REST + MCP Streamable HTTP） |

可执行文件按平台不同，**这条是跨平台时最容易踩的坑**：

| 平台 | 可执行文件 | 等价的模块调用 |
| --- | --- | --- |
| Windows | `.venv\Scripts\utf8-search.exe` | `.venv\Scripts\python.exe -m utf8_search` |
| Linux / macOS | `.venv/bin/utf8-search` | `.venv/bin/python -m utf8_search` |

> ⚠️ Linux / macOS 上**没有** `Scripts\` 目录、也**没有** `.exe` 后缀。把 Windows 路径抄到 Linux 会让 MCP 客户端拉不起子进程，界面上通常只显示 `unknown (0 tools)`，且不提示具体原因。

### 1.3 鉴权（可选，建议远程部署时开启）

```powershell
$env:UTF8SEARCH_API_KEYS="key1,key2"   # 留空 = 关闭鉴权
$env:UTF8SEARCH_RATE_LIMIT_RPM="60"    # 每个 Key 每分钟请求上限，0 = 不限
```

其他关键环境变量见 `.env.example`。

## 3. MCP stdio 接入

所有 stdio 客户端都是「启动一个子进程 + 通过 stdin/stdout 走 MCP 协议」，配置只是外壳不同。

- Windows 下 `command` 必须是**绝对路径**，JSON 里反斜杠要写成 `\\`；Linux / macOS 下同样用绝对路径（例如 `/root/utf8-search/.venv/bin/utf8-search`），但**不要**带 `.exe`、也不要用 `Scripts/`。
- 通过 `env` 传配置；**注意 stdout 是协议通道**，本服务的日志一律走 stderr，不会污染协议。

### 3.1 Claude Desktop

配置文件：`%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "utf8-search": {
      "command": "C:\\Users\\86159\\Desktop\\utf8-search\\.venv\\Scripts\\utf8-search.exe",
      "args": [],
      "env": {
        "UTF8SEARCH_SEARXNG_URL": "http://127.0.0.1:8888",
        "UTF8SEARCH_TRUST_ENV": "false",
        "UTF8SEARCH_LOG_LEVEL": "WARNING"
      }
    }
  }
}
```

改完配置需**完全退出并重启** Claude Desktop。

### 3.2 Codex

配置文件：`~/.codex/config.toml`（本机为 `C:\Users\86159\.codex\config.toml`）

Windows：

```toml
[mcp_servers.utf8-search]
type = "stdio"
command = 'C:\Users\86159\Desktop\utf8-search\.venv\Scripts\utf8-search.exe'
startup_timeout_sec = 60

[mcp_servers.utf8-search.env]
UTF8SEARCH_SEARXNG_URL = "http://127.0.0.1:8888"
UTF8SEARCH_TRUST_ENV = "false"
UTF8SEARCH_LOG_LEVEL = "WARNING"
```

Linux / macOS（以服务部署在 `/root/utf8-search` 为例）：

```toml
[mcp_servers.utf8-search]
type = "stdio"
command = '/root/utf8-search/.venv/bin/utf8-search'
startup_timeout_sec = 60

[mcp_servers.utf8-search.env]
UTF8SEARCH_SEARXNG_URL = "http://127.0.0.1:8888"
UTF8SEARCH_TRUST_ENV = "false"
UTF8SEARCH_LOG_LEVEL = "WARNING"
```
写完先自检 `command` 指向的文件真的能启动 —— 最快的办法是直接喂一个 `initialize` 帧（把 `<command 的值>` 换成你上面实际写的路径）：

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"0"}}}' | <command 的值>
```

返回的 JSON 里含 `"serverInfo"`（例如 `"name":"utf8-search"`）说明可执行文件与 stdio 通道都正常；
若报 `command not found` / 路径不存在，就是 `command` 写错了（Linux 上最常见的是沿用了 Windows 的 `Scripts\...exe`）。

仓库里还有一条更完整的两通道自检（握手 + 工具发现 + 真实调用，服务端实测 6 项全过）：

```bash
# Linux / macOS
.venv/bin/python -u scripts/mcp_selfcheck.py --mode stdio,stdio-raw
# Windows
.venv\Scripts\python.exe -u scripts\mcp_selfcheck.py --mode stdio,stdio-raw
```

**改完 `config.toml` 需要重启 Codex 会话**，否则不会重新拉起 MCP 子进程。

若服务跑在另一台机器上、希望 Codex 走 HTTP：Codex 的 MCP HTTP 传输支持随版本演进，**较新版本**可直接写：

```toml
[mcp_servers.utf8-search-http]
type = "streamable_http"
url = "http://<服务地址>:8000/mcp"
```

若你的 Codex 版本不支持该 `type`，改用 stdio + 本地桥接（例如 `npx -y mcp-remote http://<服务地址>:8000/mcp`），或直接调用 REST（见第 5 节）。

## 4. MCP over HTTP（Streamable HTTP）

```powershell
$env:UTF8SEARCH_API_KEYS="test123"
utf8-search serve --host 0.0.0.0 --port 8000
```

- 端点：`http://<host>:8000/mcp`（`GET /mcp` 返回 400 属正常，MCP 握手走 POST）。
- **未鉴权时客户端可能显示 `Auth: Unsupported` / 状态 `unknown`，属预期而非故障**：服务端对未带 Key 的请求返回 401，且**不带 `WWW-Authenticate` 响应头**，MCP 客户端因此探测不到 OAuth 端点。判断是否真正连上，看**工具有没有列出来**（`web_search` / `web_fetch`）；HTTP 传输的 Key 走静态 `Authorization: Bearer` 头（各客户端配置见第 3 节）。
- **部署到公网域名或反向代理后面时，必须配置允许的 Host**，否则返回 421：

```powershell
$env:UTF8SEARCH_MCP_ALLOWED_HOSTS="search.example.com,1.2.3.4:8000"
```

Python 客户端示例（MCP SDK v2）：

```python
import asyncio
from mcp import Client

async def main() -> None:
    async with Client("http://127.0.0.1:8000/mcp") as client:
        tools = await client.list_tools()
        print([t.name for t in tools.tools])
        result = await client.call_tool("web_search", {"query": "最新的 AI 政策", "search_depth": "deep"})
        print(result.structured_content["results"][0]["title"])

asyncio.run(main())
```

## 5. REST 接入

```powershell
# 搜索（Tavily 兼容）
curl.exe -X POST http://127.0.0.1:8000/v1/search `
  -H "Content-Type: application/json" -H "X-API-Key: test123" `
  --data-binary "@body.json"
```

`body.json`：

```json
{
  "query": "2026年 人工智能 政策",
  "max_results": 5,
  "search_depth": "advanced",
  "topic": "general",
  "include_raw_content": false
}
```

响应（与 Tavily 字段对齐）：

```json
{
  "query": "2026年 人工智能 政策",
  "results": [
    {"title": "...", "url": "...", "content": "...", "raw_content": null,
     "score": 0.99, "engine": "yahoo", "published_date": null}
  ],
  "response_time": 2.5,
  "request_id": "5f66...",
  "auto_parameters": {"topic": "general", "search_depth": "advanced"},
  "usage": null,
  "cached": false,
  "depth": "advanced",
  "pages_read": 6,
  "engines_used": ["searxng"],
  "failed_engines": []
}
```

抽取：

```json
{"urls": ["https://example.com"], "format": "markdown", "max_chars": 5000}
```

返回 `results[]`（含 `url` / `raw_content` / `title` / `chars`）与 `failed_results[]`。

### 参数说明

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `search_depth` | `basic` / `advanced` / `deep` | basic 只搜索；advanced 抓取约 6 页；deep 抓取约 24 页（对标「读几十个网页」） |
| `topic` | `general` / `news` | news 走新闻类目 |
| `days` | int | Tavily 风格，内部换算为 `time_range` |
| `time_range` | `day` / `week` / `month` / `year` | 时间范围过滤 |
| `include_domains` / `exclude_domains` | string[] | 站点白名单 / 黑名单 |
| `include_raw_content` | bool | 是否返回完整正文 |
| `max_pages` | int | 覆盖深度模式的抓取页数 |

## 6. Dify 与 n8n

### 6.1 Dify（不支持 MCP，用 REST）

「工具 → 自定义工具 → 创建」，导入如下 OpenAPI 片段（把 `servers.url` 换成你的地址）：

```yaml
openapi: 3.0.0
info:
  title: utf8-search
  version: 0.1.0
servers:
  - url: http://127.0.0.1:8000
paths:
  /v1/search:
    post:
      operationId: webSearch
      summary: 联网搜索
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [query]
              properties:
                query: {type: string, description: 查询词}
                max_results: {type: integer, default: 5}
                search_depth: {type: string, enum: [basic, advanced, deep], default: basic}
      responses:
        "200":
          description: OK
```

鉴权在「授权方式」里选 API Key，Header 名填 `X-API-Key`。

## 7. Tavily 兼容替换

服务返回的字段与 Tavily 保持一致，已有代码通常只需改 `base_url`：

```python
# 原：client = TavilyClient(api_key="tvly-xxx")
# 现：
import httpx

client = httpx.Client(base_url="http://127.0.0.1:8000",
                      headers={"X-API-Key": "test123"})
resp = client.post("/v1/search", json={"query": "OpenAI API 定价", "max_results": 5,
                                      "search_depth": "advanced"}).json()
```

| Tavily 能力 | 本服务 | 说明 |
| --- | --- | --- |
| `POST /search` | 支持 | `/search` 与 `/v1/search` 等价 |
| `POST /extract` | 支持 | `/extract` 与 `/v1/extract` 等价 |
| `search_depth` | 支持 | 额外提供更强的 `deep` |
| `topic` / `days` / `time_range` | 支持 | `days` 内部换算为 `time_range` |
| `include_domains` / `exclude_domains` | 支持 | — |
| `include_raw_content` | 支持 | — |
| `answer`（自带 LLM 摘要） | 不做 | 设计上不内置 LLM，摘要交给调用方模型 |
| `images`（顶层与 `results[].images`） | 不做（恒空数组） | 字段已补齐，按字段遍历的客户端不会 KeyError |
| `results[].favicon` | 不做（恒 `null`） | M6 补齐字段 |
| `results[].id` | 支持 | `<request_id>-<序号>`，可用于去重/引用 |
| `response_time` / `request_id` / `auto_parameters` / `usage` | 支持 | `usage.credits` 恒 0（本服务免费）；`auto_parameters` 回显实际生效的 `topic`/`search_depth` |
| 未实现的 Tavily 参数（`chunks_per_source`、`start_date`/`end_date`、`country`、`language`、`safe_search`、`exact_match` 等） | **接受但忽略** | 直接换 `base_url` 的客户端不会因多传参数而报错 |

逐字段对照矩阵（含错误码与限流语义、有意保留的差异与理由）：
[`docs/reports/m6-tavily-compat-20260928.md`](reports/m6-tavily-compat-20260928.md)；
官方字段清单与示例响应留档：[`docs/reports/tavily-official-search-20260928.md`](reports/tavily-official-search-20260928.md)。

### 7.1 客户端该期待什么 / 不该期待什么（有意保留的 7 条差异）

接入方按这张表设预期即可；每一条都对应报告 §6 的差异项，**不是 bug**。

| # | 差异 | 你会看到 | 不该期待 | 客户端适配建议 |
| --- | --- | --- | --- | --- |
| 1 | **`answer` 恒 `null`**（本服务不自带 LLM） | `include_answer=true` 时字段存在但为 `null`；`false` 时该键不出现（与 Tavily 习惯一致） | 不要期待一段摘要文本 | 需要摘要就用你自己的模型对 `results[].content` 再生成 |
| 2 | **图片字段恒空** | 顶层 `images: []`、`results[].images: []`、`results[].favicon: null` | 不要期待任何图片 URL / favicon | 遍历代码安全（不会 KeyError），但要把空数组当"没有图片"处理 |
| 3 | **`results[].id` 格式不同** | 形如 `<request_id>-<序号>`（Tavily 是不透明短 id） | 不要解析它的内部结构 | 只当字符串 id 用（去重/引用都够） |
| 4 | **`score` 量纲不同** | 本地融合分（引擎权重 + 时效 + 去重）；**自 2026-09-30（P7）起 `score` 保持原始相关性分**，排序位序由内部 `score × 形态乘子` 决定 | 不要与 Tavily 的分数横向比较、不要套阈值；**不要假设数组位序与 `score` 单调一致** | `score` 只当同一响应内的相关性参考；**要保留我们的排序就直接用数组顺序**，不要用 `score` 自行重排 |
| 5 | **`usage` 语义不同** | 仅 `include_usage=true` 时出现，`{"credits": 0}` | 不要期待真实计费数字 | 计费代码不必分支——恒 0（免费） |
| 6 | **`response_time` 是数字** | 例如 `2.5`（**官方文档"示例响应"里写成字符串 `"1.67"` 是笔误，其 schema 类型是 number**） | 不要按字符串处理 | 直接当数值；若要两种都兼容用 `float(x)` |
| 7 | **未实现的 Tavily 参数被忽略** | `chunks_per_source`、`start_date`/`end_date`、`include_published_date`、`filter_by_published_date`、`include_image_descriptions`、`include_favicon`、`include_domains_mode`、`country`、`language`、`filter_by_language`、`auto_parameters`、`exact_match`、`safe_search` 传了**不报错** | 不要期待它们生效 | 需要过滤请用已实现的 `time_range` / `include_domains` / `exclude_domains` / `topic=news`；语言固定 `all`（中英兼顾） |

**排序位序不再与 `score` 单调一致**（P7 起）：`score` 保持原始相关性分（对外语义不变），排序在内部按
`score × 形态乘子` 计算（对「含实质内容的首页/栏目页」轻微降权），以让独立文章更靠前 ——
因此**不要用 `score` 自行重排结果**，要保留我们的排序就用数组顺序。

**另外三条与"预期"相关的边界**（同一份报告 §1/§3 有完整说明）：

- `search_depth` 只接受 `basic` / `advanced` / `deep`（**没有** `fast`/`ultra-fast`）、`max_results` 上限 **20**；
  越界与其它参数非法一律返回 **400**（已对齐 Tavily，官方 SDK 会抛 `BadRequestError`）；
- 错误体：我们保持 `detail` 为字符串（Tavily 是 `detail.error`），但**额外给了顶层 `error`** 可读消息；
  `429` 继续带 `Retry-After`。官方 SDK 对这种 `detail` 形态有 try/except 兜底、不会崩。
- MCP 客户端面板里的 `Auth: Unsupported` / `unknown`：见第 4 节的说明，**看工具有没有列出来**判断连通性；

**关于校验错误码的统一 400（决策）**：官方错误表里「语义非法」是 400、而「形状校验失败」的示例标的是 422；
我们**不做「形状 422 / 语义 400」的逐类分流**，统一返回 400。理由：① 官方 SDK 里没有 422 分支，
真 Tavily 的形状错误同样走 `raise_for_status()` 通用分支 —— 统一 400 是**超集行为**，不会打断任何在
真 Tavily 上跑得通的客户端；② 分类依据脆弱：形状与语义边界模糊（`topic` 缺字段 vs 值写错同属 `Literal` 校验），
分流要按 pydantic 的 `type` 字符串硬编码归类，每加字段都要重判；③ 收益只对「照官方 422 示例写死状态码」的
客户端有效，这类客户端基本不存在。将来若确有客户端要求，改一处异常处理器即可
（详见 [`docs/reports/m6-tavily-compat-20260928.md`](reports/m6-tavily-compat-20260928.md) §7 与 `docs/04` §8 遗留任务）。

## 8. 鉴权与限流

- **鉴权**：配置了 `UTF8SEARCH_API_KEYS` 才启用；`GET /health` 不需要鉴权。
- 三种传 Key 方式：`Authorization: Bearer <key>`、`X-API-Key: <key>`、请求体里的 `api_key` 字段。
- **限流**：滑动窗口，按 Key 计；超限返回 **429**。`UTF8SEARCH_RATE_LIMIT_RPM=0` 表示不限。
- 未配置 Key 时服务会打印告警：HTTP 接口处于开放状态，**不要直接暴露到公网**。

## 9. 自研 Agent 示例

三种接入方式各自只需要一个依赖：MCP 用 `pip install mcp`，REST 用 `pip install httpx`。
下面三段可直接复制运行（假设服务在本机、Key 为 `test123`）。

### 9.1 MCP stdio（把自己当成 Claude Desktop）

```python
import asyncio
import sys

from mcp import ClientSession
from mcp.client.stdio import StdioServerParameters, stdio_client


async def main() -> None:
    params = StdioServerParameters(
        command=sys.executable,  # 也可写 utf8-search.exe 的绝对路径
        args=["-m", "utf8_search", "stdio"],
        env={"UTF8SEARCH_SEARXNG_URL": "http://127.0.0.1:8888"},
    )
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            print([tool.name for tool in (await session.list_tools()).tools])
            result = await session.call_tool(
                "web_search", {"query": "2026年 新能源汽车 补贴政策", "max_results": 5}
            )
            for item in result.structured_content["results"]:
                print(item["title"], item["url"])


asyncio.run(main())
```

### 9.2 MCP Streamable HTTP（带鉴权）

```python
import asyncio

from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client
from mcp.shared._httpx_utils import create_mcp_http_client


async def main() -> None:
    http_client = create_mcp_http_client(headers={"X-API-Key": "test123"})
    async with streamable_http_client(
        "http://127.0.0.1:8000/mcp", http_client=http_client
    ) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            result = await session.call_tool("web_fetch", {"urls": ["https://example.com"]})
            print(result.structured_content["results"][0]["raw_content"][:200])


asyncio.run(main())
```

> 服务未开鉴权时可以用更省事的高层客户端：`from mcp import Client`，然后
> `async with Client("http://127.0.0.1:8000/mcp") as client: await client.call_tool(...)`。

### 9.3 REST（Tavily 兼容）

```python
import httpx

with httpx.Client(
    base_url="http://127.0.0.1:8000", headers={"X-API-Key": "test123"}, timeout=60
) as client:
    found = client.post(
        "/v1/search",
        json={"query": "2026年 AI 政策", "search_depth": "deep", "max_results": 8},
    ).json()
    page = client.post(
        "/v1/extract", json={"urls": [found["results"][0]["url"]], "max_chars": 5000}
    ).json()
    print(page["results"][0]["chars"], "字符")
```

> 这三段与 `scripts/mcp_selfcheck.py` 里用的客户端完全同源 —— 自检脚本本身就是「一个自研 Agent」。

## 11. 常见问题

**Q1：本机 SearXNG 返回 502 / 页面抓取全部超时**
Windows 上若开启了系统代理（Clash / V2Ray 等），httpx 会把回环请求也发给代理并收到 502。本服务默认让 `127.0.0.1,localhost,[::1],searxng` 绕过代理直连。
若本机代理本身不稳定（表现为**外网抓取也大面积超时、`curl https://example.com` 也卡住**），把环境代理整个关掉改用直连：

```powershell
$env:UTF8SEARCH_TRUST_ENV="false"     # 忽略系统/env 代理，全部直连
```

注意：**Docker 里的 SearXNG 不读取 Windows 系统代理**，它走容器自己的出口（实测与美国代理出口同一 IP）。因此本机 httpx 抓取失败、而 SearXNG 仍能返回结果，是「宿主代理与容器出口不一致」的典型表现——此时优先怀疑宿主侧代理。

反之，若本机只有「HTTP 代理模式」的 VPN、关掉代理就出不了网，则显式指定：

```powershell
$env:UTF8SEARCH_HTTP_PROXY="http://127.0.0.1:7897"
```

**Q2：MCP over HTTP 返回 421**
配置 `UTF8SEARCH_MCP_ALLOWED_HOSTS`，填入实际访问用的 Host（域名或 `IP:端口`）。
未配置时 MCP SDK 只放行**本机 Host**（`127.0.0.1` / `localhost` / `[::1]`），因此从另一台机器用
`http://192.168.x.x:8000/mcp` 访问也会被 421 拒绝 —— 把 `192.168.x.x:8000` 加进白名单即可。
（自检脚本里「伪造 Host → 421」验证的就是这条防 DNS 重绑定防护。）

**Q3：首次调用很慢或失败**
SearXNG 冷启动需要 20–60 秒加载引擎；先 `curl http://127.0.0.1:8888/healthz` 确认就绪。

**Q4：结果条数变少、`failed_engines` 里有引擎名**
原因通常是 SearXNG 容器**没起来**或**引擎名单被改坏**，而不是引擎不够用。本服务默认配置了 13 个实测可用引擎（`searxng/settings.yml` 里 `keep_only` + `disabled: false` 双重配置），单次查询可拿 80+ 条原始结果。
排查顺序：① `curl http://127.0.0.1:8888/healthz` 是否 200；② `curl "http://127.0.0.1:8888/search?q=test&format=json"` 是否有 `results`；③ 逐引擎单测：`engines=<名字>`，**且不要同时传 `categories`**（两者会叠加，显式引擎列表会失效），否则不能凭「返回了结果」判断该引擎可用。
少数机会型引擎（`reloado` / `yep` / `brave` / `quark`）会间歇被限流，失败极快、代价可忽略；若全部失效，服务会自动降级到 Bing HTML 直取兜底，并在 `engines_used` / `failed_engines` 中如实上报。

**Q5：deep 模式有多快、读多少页**
实测（美国出口 IP，冷启动缓存）：deep P50 ≈ 9.2 s，平均读取 **16.2** 个页面（单次 14–19 页）；advanced P50 ≈ 3.8 s（读 3 页）；basic P50 ≈ 1.0 s。详见 `docs/01` 第 5 节。

**Q6：/extract 返回 failed_results，提示「属于保留网段」/「不允许访问」**
这是 SSRF 防护在生效：默认拒绝抓取内网与保留地址（127.0.0.1、10.x、192.168.x、169.254.169.254 等）以及 localhost、.internal 等内网主机名，只放行 http/https。公网部署请保持开启。
若你确实在内网环境自用（例如抓内网 wiki），可显式关闭：

```powershell
$env:UTF8SEARCH_BLOCK_PRIVATE_HOSTS="false"
```

> 关闭后请**不要**把服务暴露到公网；该开关只影响 `/extract` 与 `web_fetch` 的抓取校验。`UTF8SEARCH_MAX_REDIRECTS` 可改重定向跳数上限（默认 5）。
