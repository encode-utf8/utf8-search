## 0. 摘要（含一处必须更正的结论）

1. **按你的设计实现了两件事**：① `sina` 加进「透传 time_range 的日期回补路」（`news_general_engines`）；
   ② 把全局布尔 `news_pass_time_range` 改成**按引擎白名单** `news_time_range_engines`（默认只含 `sina`），
   新闻主题下白名单引擎带 `time_range` 单独发一次、其余引擎不带，结果合并去重（仍在同一个闸门槽位内）。新增 6 条离线单测。
2. **但门槛没有变好：脚本路径 28% → 28%（中文组 0/25、英文组 11/15，与改动前逐条一致）**。
3. **必须更正一条我先前的数据**：上一轮报告里「`sina` + `time_range=day` = 143 条结果 / 90 条 7 日内、中位 0.6 天」
   是**假象** —— `sina`（和 `bilibili`）**没有注册**在现网 `searxng/settings.yml`，
   单独点名 `engines=sina` 时 SearXNG **静默丢弃**该名字并**回退到默认引擎集合**，
   那 90 条带日期结果其实来自 `yandex/yahoo/naver`。
   在**确实注册了 sina** 的探针容器里复测：**sina 60 条结果、0 条带发布日期** ⇒ **sina 不可能改善「带日期比例」门槛**。
4. **真正的瓶颈是路径/判据（结构性），不是「源不够」也不是「加个源就行」**（§5）：
   主源有结果时 `_needs_general_extra` 按「结果数 < max_results」判断，chinaso 给了 5-10 条**过期但字面匹配**的结果
   ⇒ 日期回补路**根本不触发**；主源 0 条时 **Bing 兜底先填满 5 条**（离题、无日期）⇒ 回补路同样不触发。
5. 结论与建议见 §6（需你拍板），本轮按「不盲调参数」只做实现 + 归因。

## 2. B) 改动（代码）

### 2.1 `config.py`

- `news_general_engines` 默认值：`…,brave,quark,360search` → `…,brave,quark,sina`
  （**移除已从 SearXNG 删除的 `360search`**，按你的要求加入 `sina`）。
- 新增 `news_time_range_engines`（默认 `sina`）+ 属性 `news_time_range_engine_set`；
  `news_pass_time_range` 保留为**旧开关**（`true` = 全部新闻引擎透传，仅排障用）。
  注释里写明「`duckduckgo news` 带 `time_range=day` 返回 0 条，而 `sina` 需要它」这类**逐引擎相反**的实测事实。

### 2.2 `providers/searxng.py`

- `_search_impl` 拆成「编排 + `_search_once`」：先按 `_time_range_groups()` 把引擎分成
  **白名单组（带 `time_range`）/ 其余组（不带）**，各发一次请求后**按 URL 去重合并**；
  `unresponsive` / `constraint_ignored` / `raw_result_count` 在拆分时**聚合**，不会被后一次覆盖。
- 非新闻主题（含 news 的「日期回补补充路」）**保持原样**：单次请求、`time_range` 直接透传。

## 5. 归因：为什么中文组还是 0%（不是源不够，也不是 sina 能救）

证据来自 `data/measure/news-sina-20260930/decompose-after.txt`（逐条打印 `engines_used` 与每条结果的来源引擎）：

| 查询 | 主源结果 | `engines_used` | 日期回补路是否触发 | 结论 |
| --- | --- | --- | --- | --- |
| 2026年9月 国内外重大新闻 | 0（chinaso server error + google news CAPTCHA） | **`['bing']`** | ❌ 未触发 | **Bing 兜底先填满 5 条**（离题、无日期），回补路的 `_needs_general_extra` 看到 hits≥5 就不再补 |
| 最近一周 AI 行业动态 | 0 | **`['bing']`** | ❌ 未触发 | 同上（Q2 的离题结果就来自这里） |
| 台风 最新消息 路径 | 5（chinaso + duckduckgo news，**全部过期**） | `['searxng']` | ❌ 未触发 | 判据是「结果数 < 5」，而主源给了 5 条**过期但字面匹配**的 → 满足数量、不满足新鲜 |
| 美国 关税 最新政策 | 5（同上，8-526 天前） | `['searxng']` | ❌ 未触发 | 同上 |
| 2026年 新能源汽车 补贴政策 | 5（全部 chinaso，60-104 天前） | `['searxng']` | ❌ 未触发 | 同上 |
| latest semiconductor / OpenAI / EU AI Act | 3-29（duckduckgo news） | `['searxng']` | 否（够 5 条） | 英文组天然达标 |

**加上更正后的源事实**（探针容器、引擎确实注册，6 条中文查询）：

| 引擎 | 无 `time_range` | `time_range=day` | 带发布日期 |
| --- | --- | --- | --- |
| `sina` | 60 条 | 60 条 | **0 / 60（一条都没有）** |
| `chinaso news` | 32 条 | **0 条** | 32/32（不带 range 时） |
| `tiger news` | 60 条 | **0 条** | 60/60（不带 range 时） |
| `bilibili` | 120 条 | 120 条 | **120/120**（但视频站，按你的要求不加） |

⇒ 结论三句话：
1. **不是「源不够」**：通用引擎集合在 `time_range=day` 下有带日期的中文结果（实测 yandex 15、yahoo 10、naver 3 条/查询，样例中还有 2026-09-29 的「美国进口禁令生效—新京报」这种对题结果）。
2. **也不是「换个源就行」**：`sina` 根本没日期；`chinaso news`/`tiger news` 遇 `time_range` 直接 0 条；唯一全能的是视频站 `bilibili`。
3. **卡在判据与路径顺序**：`_needs_general_extra` 用「结果数不足」当判据 → 过期的字面命中就把回补路挡在门外；
   主源 0 条时又被 **Bing 兜底先占位**。这解释了「中文组 0%」而不是「源不可用」。

## 6. 建议（下一轮，需你拍板；本轮不实现）

1. **把日期回补路的触发判据从「结果数 < max_results」改成「7 日内结果数 < max_results」**（新鲜度缺口驱动），
   并给出前后对照（预计中文组会明显改善，但要防「垃圾新鲜结果」冲淡相关性 → 同时看 2-9 与卫生度）。
2. **Bing 兜底不应抢占新闻时效路径**：主源 0 条时应先走「带 `time_range` 的日期回补路」，Bing 只作最后兜底
   （顺带解决 Q2 那类「短剧站/动漫站」离题结果）。
3. **源侧再评估**（不是盲调参数）：`yandex` 配合 `time_range` 当年因「垃圾农场」被排除，今天的样本看着对题
   （且有日期）；建议用 20 条 2-9 + 卫生度做一次受控 A/B，再决定是否把它加回 `news_general_engines`。
4. `sina` 要不要留在 `news_general_engines`？**我倾向撤掉**（它 0 条带日期，对「新鲜候选」这条路没贡献，
   还会稀释候选）；本轮按你的指令加了，撤不撤你定。

## 7. C) Q2 / Q6 离题结果的来源（为下一轮 ③ 备料）

复跑 `Python 3.13 新特性`（Q6）与 `最近一周 AI 行业动态`（Q2），逐条打印结果来源引擎与发布日期：

```

   #1 resulthunter 无日期  zhuanlan.zhihu.com/…        #2 resulthunter 无日期  zhuanlan.zhihu.com/…
   #3 naver        无日期  ai-bot.cn/daily-ai-news/    #4 yandex      无日期  omofuna.com/anime/…（动漫站）
   #5 yandex       无日期  woshipm.com/ai/…

   #1 yep          无日期  yanbin.blog/python-3-14-new-features-1/（3.14 不是 3.13）
   #2 yandex       无日期  blog.path-finder.jp/…（Docker 构建报错）
   #3 yep          无日期  libraries.io/pypi/QUANTAXIS-CRAWLY（包页）
   #4 fynd         无日期  formulae.brew.sh/formula/python@3.13（公式页）
   #5 fynd         无日期  phoronix.com/news/Python-3.13-Released（发布公告，非「新特性」正文）
```

**结论**：Q6 与 Q2 的 2-9 失败**都不是 Bing 兜底**，而是 **SearXNG 通用引擎（yep / yandex / fynd / resulthunter / naver）
的「字面匹配离题」**，形态是「版本号/关键词命中但主题不符或页面类型不对」（3.14 文章、包页、公式页、发布公告），
且**全部无发布日期**（所以本地时效排序也帮不上）。
**Bing 兜底只出现在 news 路径的主源 0 条时**（§5 的 Q2 news 分解里 `engines_used=['bing']`）——
两类问题成因不同，下一轮修 Bing 兜底**不会**顺带修好 Q6 这类离题。
