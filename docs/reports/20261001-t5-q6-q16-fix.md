## 2. 第 2 步：改动（只动 rank 层，每条规则都有单测）

### 规则 A：非主题页形态（治 Q6）

`rank/diversity.py` 新增 `looks_like_offtopic_index_page()` / `is_offtopic_index_page()`：

* 与 `is_aggregator_page` **同源判据**：**形态命中 且 正文无实质内容**（`has_substantive_content` 为假）才剔除；
* 形态三类：社区**个人主页**（`/member/`、`/user/`、`/people/`、`/profile`…）、
  **包索引页**（formulae.brew.sh / pypi.org / npmjs.com / crates.io / rubygems / packagist / hub.docker.com…）、
  **图片素材板**（pinterest 的 `/ideas/`、`/pin/`、`/search/`、`/board/`）；
* 接入 `apply_rank_filters` 的 `offtopic_page` 步骤：候选充足时剔除、不足时按缺陷轻重补回（不会掏空结果）；
* **复用 `drop_aggregator_pages` 开关** ⇒ 新闻路径（`structural_only=True`）完全不受影响（有单测）。

### 规则 B：修饰词精确匹配（治 Q16）

`rank/spec_tokens.py` 新增 `modifier_exact_match()`，并把它并入 `spec_mismatch` 步骤：

* 查询里的 `pro/max/plus/mini/ultra/air/se` 必须**精确出现**：**缺**（只有 iPhone 17）与
  **多**（只有 17 Pro Max）都判**不匹配**（候选充足剔除、不足补回并标 `spec_unverified`），不再是 partial 降权；
* **只看标题 + URL**（页面身份），避免页脚/导航里偶然出现的「iPhone 17 Pro」把 Pro Max 页面放进来；
* 延长判定兼容 URL 编码分隔符（`Pro+Max` / `Pro%20Max` / `Pro-Max`）—— 这是 T5 第一遍复测（`6ad4073`）
  抓到的漏判，已在 `975356d` 修复并补单测；
* 页面**同时**提到 17 Pro 与 17 Pro Max（Apple 发布会稿）仍算匹配（存在独立出现的 Pro），不误伤。
