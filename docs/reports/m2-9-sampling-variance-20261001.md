## 2. 摆动与什么同现（事实描述，不归因结论）

- **Q1 的降档与上游引擎失败同现**：每轮 Q1 的元数据里"失败引擎"分别为
  run1 `brave, google, privacywall` → 4/5；run2 再加 `yep` → 4/5；
  run3/run4/run5 = `brave, google, privacywall, resulthunter, yep`（5 个）→ 2/5。
- **Q2 的结果集整组换脸**：run1/2 的 top5 是「2 条知乎 AI 周报/周刊 + ai-bot 每日 AI 资讯 + 1 条短剧垃圾站 + 1 条产品页」→ 3/5；
  run3 整组退化为 StackOverflow 缓存问答 3 条 + 垃圾站 + 产品页（该查询卫生度：覆盖率 0.10、独立站点 3、同站冗余 1）→ 0/5；
  run4/run5 为「IT 资讯频道 + 垃圾站 + 产品页 + 社区首页/维基」→ 1/5。
- **顶部结果集的替换面比计数摆动面大得多**：20 条查询里有 **18 条**在 5 轮间至少换过一次 top5（只有 Q15、Q19 五轮完全一致；Q2/Q3/Q5/Q9/Q11/Q20 各出现 5 种不同组合），
  但其中多数替换没有带动相关数变化 —— 即**同一 commit 下 96 秒内结果集就会换，相关数只有部分查询会被带动**。

## 3. 结论（只回答两件事）

**① 单次采样的摆动区间：16–17/20，即 80%–85%（min 80%、median 80%、max 85%）。**
逐条层面：5/20 条查询出现计数摆动（Q1/Q2/Q3/Q5/Q18），最大摆动是 Q2（0–3 条）；另有 2 条查询（Q6/Q16）5 轮恒为 3。

**② 20 条样本对 90% 判据线的分辨率：1 条查询 = 5 个百分点。**
90% 对应 18/20（允许 2 条低于 4）；本轮实测的摆动带宽恰好是 1 条查询（5pp），
也就是**采样噪声与判据线的 1 条余量同量级** —— 单次采样无法把"85%"与"90%"区分开（两者只差 1 条查询），
更无法把"真实差异"与"抽样抖动"分开。要在这个量级上做判定，需要：
① 至少 3 次重复采样取中位数（本轮 5 次的中位数 = 16/20）；或
② 扩大样本：n=40 → 每条 2.5pp；n=100 → 每条 1pp（可分辨 1–2 条的差异）。

## 4. 局限

- 判官为单个 LLM（agent 初评），存在自我偏好风险；缓解手段 = 校准集先行 + 盲评（无池标签/无来源标签）+ 逐条 note 留痕。
- 边界判项（会影响计数、已在 scores 的 note 中逐条写明）：brew formula 页与 V2EX 会员页（判 0，纯元数据/纯导航）、
  techtarget HTTP 总览（勉强 1）、天极资讯频道首页（勉强 1）、内蒙古永佳商贸"工业扫地机"页（判 0，非家用扫地机器人）。
  其中 **Q6 的两条 0（V2EX、brew）若改判为 1，会使 Q6 从 3 变成 4/5**，属本报告最敏感的判项。
- 5 次采样集中在 96 秒内，度量的是"同一上游状态下的短时抖动"，**不代表跨日/跨时段的波动**（不同时段的上游健康度差异另见 `docs/04` §4.4 与长稳记录）。
