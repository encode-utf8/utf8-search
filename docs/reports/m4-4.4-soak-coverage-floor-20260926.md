# M4-4.4 长稳覆盖率下限（B 补丁）验收：SIGSTOP 受控挂起复现

- 日期：2026-09-26
- 分支：`fix/soak-longrun-metrics`（追加 commit）
- 场景：挂机进程被 `SIGSTOP` 受控挂起约 30s（采样间隔 4s），恢复后脚本按规则**不补跑**，
  错过的采样槽位逐条记 `SKIP`
- 补丁：`src/utf8_search/verify/metrics.py` 新增 `MIN_COVERAGE = 0.95`；
  覆盖率低于下限**直接判不通过**，并在结论里写明实际覆盖率

## 1. 复现方法

```bash
# 1) 起挂机（进程内流水线；缓存已预热，避免首轮真实查询拖慢时间槽对齐）
setsid .venv/bin/python -u scripts/soak.py \
  --interval 4 --max-samples 20 --duration-hours 0.5 --warmup 0 \
  --searxng http://127.0.0.1:8888 \
  --out data/soak-sigstop-<tag>.csv --json data/soak-sigstop-<tag>.json &

# 2) 等写满 5 条样本后：挂起 30s 再恢复
kill -STOP <pid>; sleep 30; kill -CONT <pid>

# 3) 采样结束后脚本打印结论（同一份 CSV 也可用 --summarize 复算）
```

> 20 个真实样本 + 5 个 SKIP = 25 个槽位，覆盖率 20/25 = **80.0%**。

## 5. 单元回归

`tests/test_verify_metrics.py`：

- `test_soak_fails_when_coverage_below_floor`：覆盖率 60% < 95% → 不通过（可用率仍 100%）；
- `test_soak_fails_when_availability_below_floor_even_if_coverage_ok`：覆盖率 100% 但可用率 80% → 仍不通过。

## 6. 结论

覆盖率（`sampled / measured`）纳入硬门槛后，「跳过大量槽位 + 其余全成功」不再能假绿；
`scripts/soak.py` 的 `--status`、在线结束结论与 `--summarize` 复算共用同一条判定路径，因此三者口径一致。
