## 4. 已知限制（如实）

* 搜索是**子串匹配**（无分词/拼音/模糊），页面规模（5 页）下足够；后续如需增强再评估；
* 站点内容来自仓库现有文档的**渲染快照**：源文档变更后必须重新生成（`--check`/单测会拦住过期提交）；
* 站点暂不收录 `docs/reports/**` 的过程报告全文（只链接稳定文档与报告索引），避免把内部实验数据暴露给使用者；
* **已部署（2026-10-03）**：`/guide` 已可公网访问；回滚步骤见 §3，`docs` 异常不影响 search 链路。

## 6. 追加：服务测试台（节点探测 + REST/MCP 调试，2026-10-03）

新增页面「**服务测试台**」（左侧分组「测试」），**纯前端**完成两类测试，不新增任何后端接口：

### 6.1 节点状态：逐引擎探测

* 先读 `GET /health`：展示 `status / searxng / version`、活跃引擎列表、以及**冷却引擎**（原因 + 剩余秒数）；
* 再对勾选的活跃引擎逐个发最小请求 `POST /v1/search {query, max_results≤5, engines:[E]}`（顺序执行、间隔 250ms），
  输出每个引擎的：**HTTP 状态、延迟、结果数、真实命中数**；
* **防假绿**：判定同时核对 `failed_engines` 与每条结果的 `engine` 字段 —— 例如实测 `engines:["brave"]`
  返回 `failed_engines=["brave"]` 且 3 条结果来自 `bing`，页面上标为**「回退」**而不是正常（与仓库既有「探测加固」口径一致）；
* 冷却中的引擎在列表中禁用（不参与本轮探测）。

### 6.2 请求仿真：REST / MCP 调试台

* 传输二选一：**REST** `POST /v1/search`（Tavily 兼容）或 **MCP** `web_search`；
* 参数表单（查询 / max_results / depth / topic）一键生成**最小请求** JSON，也可直接手改文本框；
* REST：展示 HTTP 状态、耗时、原始返回（JSON 自动美化）；
* MCP：自动完成 **`initialize → notifications/initialized → tools/call`** 三段握手，
  展示每段耗时与 session id，解析 SSE（`data:` 行）后把 `content[0].text`（搜索结果 JSON）美化展示。

### 6.3 安全与使用前提（如实）

* **Key 只留在浏览器**：用于直连 API（`Authorization: Bearer`），不经说明站服务器；「记住」只写 `sessionStorage`（默认不勾）；
* **同源前提**：从公网 `https://<域名>/guide/` 打开时，页面与 API 同源，浏览器可直接请求；
  若从本机 `http://127.0.0.1:8080` 直开并指向 `:8000`，属跨域，**浏览器会按 CORS 拦截**（服务端未开 CORS，属预期）；
* 探测是真实上游请求：会消耗 RPM 配额（默认 60/min），逐引擎探测按顺序 + 250ms 间隔，仍建议不要连续狂点。
