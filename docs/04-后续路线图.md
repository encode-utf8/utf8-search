## 4. M4 详细任务（P0，建议先做）

### 4.1 SSRF 防护（最高优先级）

**问题**：`/extract`、`web_fetch` 直接抓取调用方给的 URL，公网部署后可被用来探测内网（`http://127.0.0.1:6379`、`http://169.254.169.254/latest/meta-data/` 等）。

**实现**：新增 `src/utf8_search/security.py`，在 `PageExtractor._download` 之前做校验：

- 仅允许 `http` / `https`；
- DNS 解析后校验所有解析结果都不落在保留网段：`0.0.0.0/8`、`10/8`、`127/8`、`169.254/16`、`172.16/12`、`192.168/16`、`100.64/10`、`224/4`、`::1`、`fc00::/7`、`fe80::/10`；
- **重定向必须逐跳复检**（httpx 的自动跟随会绕过校验，需改为手动跟随）；
- 限制重定向次数（默认 5）；
- 新增配置 `UTF8SEARCH_BLOCK_PRIVATE_HOSTS`（默认 `true`，内网自用可关）。

**验收**：新增单测覆盖上述每类地址；`curl /v1/extract` 传 `http://127.0.0.1:8888` 应被拒绝。

### 4.2 云服务器部署验收

- Linux VPS + `docker compose up -d`，验收 SearXNG + 应用均健康；
- 反向代理（Caddy / Nginx）+ HTTPS，配置 `UTF8SEARCH_MCP_ALLOWED_HOSTS`；
- 开启 `UTF8SEARCH_API_KEYS`，确认 401 / 429 行为；
- `data/` 卷持久化验证（重启后缓存仍在）；
- 产出：`docs/05-服务器部署手册.md`。

### 4.3 真实客户端联调

按 `docs/03` 逐个跑通并记录（日志或截图）：Claude Desktop、Codex、Cursor、Cherry Studio、Dify、n8n、自研 Agent。任一客户端跑不通则回修文档或代码。

### 4.4 补完 M3 三项验收

- **3-3 并发压测**：新增 `scripts/loadtest.py --concurrency 10 --n 50`，验收无 5xx、无超时，记录 P95。
- **3-4 24 h 长稳**：定时（如每 5 分钟）查询一次，记录 RSS 与成功率，验收可用率 ≥ 99%、内存无持续增长。
- **2-9 相关性抽检**：20 条中英查询（覆盖新闻 / 技术 / 政策 / 商品），人工打分表格，验收 top5 中 ≥ 4 条相关。

## 5. M5 详细任务（P1）

### 5.1 引擎健康度自适应

- 在 `SearxngProvider` 内维护每个引擎的滑动统计（成功率、P50 延迟、最近失败次数）；
- 每次查询动态生成 `engines` 参数：剔除连续失败的引擎、按成功率排序；
- 目标：被限流引擎不再占用聚合等待时间，basic P50 进一步下降。

### 5.2 时效性增强

- `topic=news` 切换到新闻类目引擎（`sogou wechat` / `yahoo news` / `google news` / `naver news` / `wikinews`），并实测后择优；
- `published_date` 缺失时用 `htmldate`（trafilatura 已依赖）从页面提取；
- 验收：`topic=news` + `time_range=day` 返回结果中 ≥ 80% 带 7 日内日期。

### 5.3 中文源强化

- 持续跟踪 `quark`（夸克）与 `sogou` 的可用性，评估是否值得做独立 Provider 而非走 SearXNG；
- 评估 `sogou wechat`（微信公众号）作为中文时效性补充。

## 8. 前置条件与风险

- **需要用户提供**：一台可自由出网的云服务器（用于 4.2）；是否要立刻做公网部署。
- **风险**：免费引擎的可用性会随上游策略变化，`searxng/settings.yml` 的名单需定期复测（建议每季度跑一次逐引擎实测）。
- **风险**：公网开放 `extract` 接口前，4.1 必须先做完。
- **已知限制**：`answer`（自带 LLM 摘要）与 `images` 明确不做。
